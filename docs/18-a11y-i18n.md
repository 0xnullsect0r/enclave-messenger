# Accessibility and Localization

Status: Draft (M0) · Normative

Source: PLAN.md §16, §14 (accessibility gate). Design tokens: `design/tokens.toml`. The screen-reader gate itself is in `15-client.md` §3.

## 1. Accessibility (WCAG 2.2 AA)

### 1.1 Requirements

| # | Requirement | How it is met | Checked by |
|---|---|---|---|
| A-1 | Token contrast | `cargo xtask tokens-check` on every pair in `17-design.md` §3.2 | CI |
| A-2 | Visible focus | A 2 px focus ring, Pine in light mode and Saffron in dark mode, ≥3:1 against every background it can appear on | CI (tokens) and manual |
| A-3 | Full keyboard navigation on desktop | Every action reachable by keyboard; logical tab order; shortcuts listed in Help; no keyboard traps | `slint::testing` scripts |
| A-4 | Labels on every control | Including bubble metadata ("Sent, read", "Delivered late") and icon-only buttons | Screen-reader scripts |
| A-5 | 200% text | OS text scaling up to 200% with no truncation of message text | Screenshot tests at 100/150/200% |
| A-6 | No information by color alone | Every state has a shape and words (`17-design.md` §6.5) | Design review, grayscale screenshots |
| A-7 | Reduce motion | Honor the OS setting; animations become cross-fades; the Seal close is instant | `slint::testing` |
| A-8 | Touch targets | At least 48 × 48 dp | Layout lint |
| A-9 | Captions and transcripts for voice notes | Optional on-device transcription (M11); a manual text caption field before that | M11 |
| A-10 | Errors identified in text | Every error is a sentence that says what happened and what to do | Copy review |
| A-11 | Security codes readable by screen readers | Read one 5-digit group at a time; words read one at a time with position ("word 3 of 10") | Screen-reader scripts |
| A-12 | Time limits | No security flow times out without warning and a way to extend, except link QR codes (30 min, with a visible countdown) | Manual |

### 1.2 Screen-reader gate

The hard gate (M1.5 and M6) is specified in `15-client.md` §3: TalkBack and VoiceOver must operate the chat list, the composer, and the verification flow; CJK and Indic IME, RTL, color emoji, 200% text, and text selection and copy must work. If the gate is still blocked 8 weeks after M6, native shells ship as a declared exception.

### 1.2a As implemented (L1)

- **A-2, A-3.** Buttons, fields, switches, conversation rows and every message are reached with Tab and act with Enter or Space, and show the 2 px focus ring (`Tokens.focus-ring`) while focused.
- **A-4.** Icon-only buttons carry labels; a message bubble reads who wrote it, what it holds (photo, sticker, voice note and its length, contact, location), the text and the time, and its delivery mark reads "Sending privately", "On its way", "Delivered", "Read" or "Not delivered yet".
- **A-5.** The system's text size sets `Tokens.text-scale` at start (GNOME's text scaling factor through the desktop portal, Windows' Accessibility → Text size, Android's font size, iOS's Dynamic Type; macOS has none), up to 200%; every type size follows it and message text wraps rather than truncating. CI renders every screen at 150% and 200% (`ENCLAVE_TEXT_SCALE`).
- **A-7.** Reduce motion is read from macOS, Windows, GNOME, Android (animations off) and iOS (Reduce Motion).
- **A-11.** The security code's ten words and the recovery words are separate accessible items, read as "Word 3 of 10: …" and "Word 3 of 24: …"; the digits are read one group of five at a time.

### 1.3 Audits

- M6 exit gate: a WCAG 2.2 AA audit plus scripted TalkBack and VoiceOver runs pass.
- Moderated usability sessions (M6 and M9) include at least one screen-reader user and one low-vision user.

## 2. Localization

### 2.1 Pipeline

- Strings use Slint `@tr()` with gettext catalogs, translated on Weblate.
- String freeze 3 weeks before each release.
- Pseudo-localization with +40% text expansion and a mirrored RTL pseudo-locale runs in CI screenshot tests.
- Dates, plurals, and numbers use ICU4X. Units follow the locale ("about 80 MB an hour").

**As implemented** (L2):

- Every string the window shows is `@tr("…")` in `app.slint` and `controls.slint` (a sentence built from parts is one string with `{}` for each part); the catalogs `crates/enclave-app/ui/lang/<lang>/LC_MESSAGES/enclave-app.po` are compiled into the program (Slint's bundled translations, no gettext library), and the person's language is chosen at start (`ENCLAVE_LANG`, else the system's locale).
- What the vault writes (status lines, errors, generic notices) is English and is translated by the app as it is shown (`enclave_app::i18n::tr`, from the same catalogs): an entry with `{}` or `{N}` matches the vault's text with a name, number or file in it and moves those parts into the translation. A notice that shows who wrote and what they wrote isn't touched.
- `cargo xtask i18n` extracts the template (`enclave-app.pot`: the `@tr` strings, and the vault's and app's sentences in Rust) and merges it into each tier-1 language's catalog, keeping translations; `--check` (CI) fails if a catalog is stale or a shown string isn't `@tr`. Catalogs are empty until people translate them (Weblate, G10): an untranslated string shows in English, and machine translation is never committed.
- Pseudo-locales `en-XA` (accented, 40% longer, bracketed) and `ar-XB` (right-to-left runs) are generated from the template, and CI renders every screenshot in both.

### 2.2 Tier-1 locales at 1.0

en, es, pt-BR, fr, de, ru, uk, fa, ar, tr, zh-Hans, zh-Hant, hi, id, ja.

### 2.3 RTL and bidi

- RTL layout and bidi rendering are a release gate for ar, fa, and he.
- Slint's RTL support is unverified; it is tested in M6 and patched upstream if needed.
- Names are sanitized (`15-client.md` §2). Message text isolates embedded runs so that a name or link cannot reorder surrounding text.

### 2.4 Scripts and fonts

- Atkinson Hyperlegible Next covers Latin; Noto Sans is bundled per shipped locale for scripts Atkinson does not cover (Arabic, Cyrillic where needed, Devanagari, CJK, and others).
- Security codes are always Western digits in Atkinson Hyperlegible Mono, regardless of locale, so that two people with different locales compare the same characters.

### 2.5 Recovery words

- Recovery words use the BIP-39 list for the user's language where one exists (English, Spanish, French, Italian, Portuguese, Czech, Japanese, Korean, Chinese Simplified, Chinese Traditional), and English otherwise.
- Import accepts any BIP-39 language (`03-identity.md` §2).
- Spoken security-code words and Seal words use the same BIP-39 list as the user's recovery words; when two people's languages differ, the security-code screen offers "Show in English" for both.

## Open questions

1. BIP-39 has no official wordlists for several Tier-1 locales (for example ar, fa, hi, ru, uk, tr, id, de). Users of those locales see English words. A project-maintained list would break interoperability with other BIP-39 tools; this spec keeps English as the fallback.
2. A-12's 30-minute link-QR countdown needs a screen-reader-friendly announcement cadence.
